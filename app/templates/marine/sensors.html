From buying to live readings

Who does each step. MarineTwin's part is already done: the address and the key are on the Live feed tab.

#StepWho
1Pick the pilot element on the Kit and cost tab and print its kit list.You
2Ask two monitoring contractors to quote against it. Say three things: each sensor carries its MarineTwin label (for example {{ channels[0]['sensor'] if channels else 'MP1-DS03-01-SG1' }}), the logger stores engineering units, and it sends readings by HTTPS POST.You
3Install the sensors, cable in conduit to a junction box above the splash zone, and the logger cabinet on the quay. Take a zero reading of every sensor.Installer
4Set the logger to send to the address on the Live feed tab with the asset's key, hourly or every 10 minutes. Give the installer the key only, never your password.Installer, with the key from you
5Watch the Live feed tab: each delivery shows with what it wrote and anything it could not place.You
6Read the results on the Structure step. A sensor that gets real readings stops being simulated; its chart, state and advice now come from the berth.MarineTwin

No logger yet? Readings a surveyor or a logger exports can still come in as a CSV file in Set up, Sensor readings.

Where a logger sends readings

HTTPS POST to this address with the key. The key lets a logger in without a password; anyone holding it can send readings to this asset, so give it only to the installer.

What the logger sends 
POST {{ endpoint }}
Authorization: Bearer {{ key }}
Content-Type: application/json

{"device": "cabinet-1", "readings": [
  {"sensor": "{{ channels[0]['sensor'] if channels else 'MP1-DS03-01-SG1' }}", "at": "2026-10-04T13:00", "value": {{ channels[0]['start'] if channels else 312 }}}
]}

Or the same columns as CSV text (sensor,at,value,note) with Content-Type: text/csv. A logger that cannot set headers can add ?key=… to the address. MarineTwin answers with what it wrote and, row by row, anything it could not place.
