Connect Google Drive

Once, on a machine with a browser. Nothing is stored in the database — a refresh token is a key to the Drive, and keeping it in the environment keeps it out of the backup it would otherwise be carried inside.

  1. At console.cloud.google.com, make a project, turn on the Google Drive API, and create an OAuth client ID of type Desktop app.
  2. Run python run.py drive-auth and sign in as the account whose Drive the backups should go to.
  3. Put the three values it prints into the environment (GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, GOOGLE_REFRESH_TOKEN), and optionally GOOGLE_DRIVE_FOLDER_ID to choose the folder.
  4. Schedule python run.py backup once a day.

Every night

One scheduled command, replacing the same file

On PythonAnywhere, under Tasks:

cd ~/Project_Management && python run.py backup

Scheduled tasks there run in UTC, so pick the hour that is midnight where you are — 21:00 UTC is midnight in Beirut in summer, 22:00 in winter; 21:00 UTC is midnight in Cairo in summer, 22:00 in winter. A free account gets one task a day.

Each run replaces the same file on Drive rather than adding another, so there is one file to look at. Drive keeps the older contents under Manage versions on that file, and its link never changes.

Putting one back

The half nobody tests until the day they need it

Download the file from Drive, put it on the server, and: 

python run.py restore project-control-backup.zip

It prints what is in the backup — which projects, how many deliverables — and asks before writing anything, then keeps the database it replaced beside the new one. Restoring is deliberately not a button on this page: it throws away everything since the backup was taken, and that should take more than a mis-click.
